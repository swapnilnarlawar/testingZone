# Config Generator — v1

Pure scripted approach. No AI, no external services, no API keys.
Deterministic diff of shell config files between platform release tags.

## What's in this repo

```
config-generator-v1/
├── README.md
├── .gitlab-ci.yml
├── public/
│   └── index.html          ← self-contained web app (GitLab Pages)
├── scripts/
│   ├── generate_config.py  ← Python CLI for CI/CD use
│   └── lib/
│       ├── parser.py       ← shell variable extractor (regex)
│       ├── differ.py       ← variable diff
│       └── generator.py    ← annotated config generator
└── docs/
    └── how-it-works.md
```

## Two ways to use it

### Option A — Web app (browser, no server needed)

1. Push this repo to your internal GitLab
2. The `pages` CI job deploys `public/index.html` to GitLab Pages automatically
3. Tenants browse to the URL, upload their `.sh` files, click **Generate**
4. Generated files download directly to their machine

The web app processes everything in the browser. No files leave the machine.
Works offline once the page loads.

### Option B — CI/CD pipeline (automated, no browser needed)

1. Add `GITLAB_TOKEN` as a masked CI/CD variable (read_repository scope)
2. Go to **CI/CD → Pipelines → Run pipeline**, set these variables:

   | Variable | Value |
   |---|---|
   | `TENANT_TYPE` | `new` or `existing` |
   | `STAGE` | `dev` / `staging` / `prod` |
   | `NEW_TAG` | `v2.4.1` |
   | `EXISTING_TAG` | `v2.3.0` *(existing tenants only)* |
   | `PLATFORM_PROJECT` | `group/tenant-deploy-pipelines` |

3. Run the pipeline → download the generated `.sh` files from the job artifacts

### Option C — Local CLI

```bash
export GITLAB_TOKEN=glpat-xxxx

python scripts/generate_config.py \
  --gitlab  https://gitlab.yourcompany.com \
  --project group/tenant-deploy-pipelines \
  --stage   dev \
  --new-tag v2.4.1 \
  --existing-tag v2.3.0 \
  --tenant-type existing \
  --out ./generated
```

No pip installs needed — Python 3.8+ stdlib only.

## What it generates

For each `.sh` file the tool annotates:

```bash
#!/bin/bash
# Tenant.sh
# Generated by Config Generator v1 — 2025-05-19T10:00:00Z
# Tenant type: existing
# Stage: dev

# Database connection
# [CHANGED - was: postgres-v1.acme.internal]
export DB_HOST="<YOUR_DB_HOST>.postgres-v2.platform.io"

# [NEW - ACTION REQUIRED]
# [FILL IN REQUIRED]
export DB_REPLICA_HOST="<YOUR_DB_REPLICA_HOST>"

export DB_PORT="5432"
export DB_NAME="acme_prod"
```

- `# [NEW - ACTION REQUIRED]` — variable is new in this release
- `# [CHANGED - was: ...]` — value changed, existing value shown
- `# [FILL IN REQUIRED]` — value contains a placeholder
- Variables removed in this release are listed in a comment block at the bottom

## Comparison with v2 (AI agent)

| | v1 (this) | v2 (AI agent) |
|---|---|---|
| Internet required | No (web app); GitLab only (CLI) | Yes (Anthropic API or Copilot) |
| Deterministic output | ✓ Always identical for same inputs | ✗ May vary slightly |
| Understands context | ✗ Regex-only, no semantic reasoning | ✓ Claude understands variable intent |
| Handles edge cases | ✗ Regex covers common patterns | ✓ Handles unusual bash constructs |
| Cost | Free | Anthropic API tokens |
| Speed | < 1 second | 10–30 seconds |
| Dependencies | Python 3.8+ stdlib | Anthropic SDK / Copilot |

**Use v1 when:** you need deterministic, fast, offline, zero-cost processing.
**Use v2 when:** you want semantic understanding, natural language interaction, and
can accept a network dependency and token cost.
